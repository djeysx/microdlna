# MicroDLNA Icons

**Consumer:** `upnphttp.c` (`send_resp_icon` function, lines 641-687)
**Generator:** `gen_icon.sh`
**Build-time selection:** Make variable `ICON` (default: `clap`)

The UPnP/DLNA server embeds 4 images (one icon, in two sizes and two
formats) compiled directly into the binary. They are no longer hand-written:
they are generated by `gen_icon.sh` from a source image, stored in
`icons/<name>/`, and the `Makefile` picks which set to use via `ICON=<name>`.

| C array    | Format | Dimensions | Served URL      |
|------------|--------|------------|-----------------|
| `png_sm`   | PNG    | 41 × 48    | `/icons/sm.png` |
| `png_lrg`  | PNG    | 102 × 120  | `/icons/lrg.png`|
| `jpeg_sm`  | JPEG   | 41 × 48    | `/icons/sm.jpg` |
| `jpeg_lrg` | JPEG   | 102 × 120  | `/icons/lrg.jpg`|

The default set is `clap` (a clapperboard icon). The `tux` set is still
available under `icons/tux/`: it's the historical penguin by Larry Ewing
(`lewing@isc.tamu.edu`), made with The GIMP, extracted as-is from the old
`icons.h` when this mechanism was put in place.

---

## 1. `icons/<name>/` layout

Each icon set lives in its own directory:

```
icons/
  clap/
    clap_sm.png
    clap_lrg.png
    clap_sm.jpg
    clap_lrg.jpg
    icons.h        <- generated, declares png_sm/png_lrg/jpeg_sm/jpeg_lrg
  my_icon/
    my_icon_sm.png
    ...
    icons.h
```

`icons/<name>/icons.h` always declares the 4 arrays under the **same
canonical names** (`png_sm`, `png_lrg`, `jpeg_sm`, `jpeg_lrg`), regardless of
`<name>` — this is what lets `upnphttp.c` stay unchanged (it just does
`#include "icons.h"`) while the actual content depends on the directory
selected at build time.

These directories are regular source files: they're committed like any
other file (no `.gitignore` entry), unlike `build/version_info.h`, which is
regenerated on every build and never committed.

---

## 2. Generating an icon set with `gen_icon.sh`

```sh
./gen_icon.sh <name> <source-image>
```

- Converts `<source-image>` (any format ImageMagick can read) into 4 files
  via `convert`, at the fixed dimensions expected by `upnphttp.c` (41×48 and
  102×120):
  - PNG: `-background white -flatten -resize WxH! -colors 256 -type Palette`
    (any transparency is flattened onto a white background, then indexed to
    8 bits).
  - JPEG: `-resize WxH! -background white -flatten -quality 95
    -sampling-factor 2x2,1x1,1x1` (baseline, 4:2:0, quality ~95).
- Packs the 4 files into C with `xxd -i`, renames the generated arrays to
  the canonical names, and writes `icons/<name>/icons.h`.

```sh
./gen_icon.sh --pack <name>
```

Variant that skips the ImageMagick conversion and packs the 4 files already
present in `icons/<name>/` directly (useful if the images already have the
right dimensions/format, or to rebuild `icons.h` after manually editing the
images).

## 3. Choosing the icon set at build time

```sh
make                 # ICON=clap (default)
make ICON=my_icon     # uses icons/my_icon/icons.h
```

Mechanism:
- `ICON ?= clap` in the `Makefile`.
- `-Iicons/$(ICON)` is added to the compile flags, so
  `#include "icons.h"` in `upnphttp.c` resolves to
  `icons/$(ICON)/icons.h`.
- A stamp file `build/.icon` records the last `ICON` used and forces a
  rebuild of `upnphttp.o` when it changes — without it, switching from
  `ICON=a` to `ICON=b` without `make clean` wouldn't trigger a rebuild (Make
  only detects changed files, not changed variables).
- If `icons/<name>/icons.h` doesn't exist, the build fails with an explicit
  Make error (`No rule to make target 'icons/<name>/icons.h'`): you need to
  run `gen_icon.sh` first.

## 4. Produced formats

### PNG (`png_sm`, `png_lrg`)

| Property            | Value                                       |
|----------------------|-----------------------------------------------|
| Bit depth             | 8                                             |
| Color type            | 3 → indexed (palette, ≤ 256 colors)          |
| Compression/filter     | 0 / 0, non-interlaced                        |
| Chunks                 | `IHDR` → `PLTE` → `IDAT` → `IEND` (no `tRNS`: source transparency is flattened onto white by `gen_icon.sh`) |

### JPEG (`jpeg_sm`, `jpeg_lrg`)

| Property              | Value                                     |
|-------------------------|----------------------------------------------|
| `APP0` marker             | JFIF                                        |
| `SOF`                      | `0xC0` baseline DCT, 8-bit, 3 components   |
| Chroma subsampling          | 4:2:0 (luma H2V2 / chroma H1V1)           |
| Quality                     | ~95                                        |

`icons/tux/` (extracted as-is from the old `icons.h`, not regenerated by
`gen_icon.sh`) keeps its original characteristics: PNG indexed at 200/256
colors **with transparency** (`tRNS`), JPEG quality ≈ 95-100. Any set
generated via `gen_icon.sh` (including `clap`) instead follows the fixed
parameters above — a white background instead of transparency, JPEG quality
95 — without aiming for a bit-for-bit reproduction.

---

## 5. History: `sizeof(...) - 1` fix

`send_resp_icon` used to compute the size to send with
`sizeof(png_sm) - 1` (and likewise for the 3 other arrays). Since the
arrays contain no padding byte, this `-1` systematically truncated the last
byte of every icon sent (the `IEND` CRC for PNGs, the `EOI` marker for
JPEGs). The `-1` had been present since the project's initial commit, with
no justification or convention that would explain it; it was removed from
all 4 occurrences in `upnphttp.c`.
